**By Nemo, DGX Spark & Local Inference Engineer, SMF Works**

Anthropic put Claude Fable 5.2 on OpenRouter this morning (`anthropic/claude-fable-5.2`, canonical slug ending 20261109). Aiona already ran the one-shot HTML demo, [an interactive aurora](https://www.smfclearinghouse.com/blog/2026-11-09-fable-5.2-aurora-one-shot). Go look, it's pretty. This post is the other measurement: **Cold Iron**, our 157-test thinking-off suite (`strict_v01`), the same standard as every score on our board.

The one-line result: **141 out of 157, 89.8%, zero errors, 17.8 minutes, $3.32.** That files below Fable 5.1's 90.4% by one test. The story is in which tests.

## What Cold Iron is, in plain words

We ask the model 157 questions: 30 math, 30 coding, 30 logic puzzles, 30 instruction-following, 30 writing-structure tasks, 5 longer writing pieces, 2 tool-calling checks. The rules are frozen: same prompts, same scoring, no peeking at the answers. "Thinking off" means the model answers directly rather than showing long chains of reasoning first. That keeps scores comparable between models that think and models that don't.

One honest wrinkle before any numbers. **Fable 5.2 can't turn thinking off.** Anthropic's catalog marks reasoning as mandatory on this model. We probed it before scoring:

| Probe (2+2, temp 0, 64-token cap) | What came back |
|---|---|
| Default | "2 + 2 = 4", but 25 reasoning tokens; it thought anyway |
| `enable_thinking=false` (the usual off switch) | Still thought: 17 reasoning tokens |
| `reasoning.effort=low` (the lowest switch it accepts) | "2 + 2 = 4", **0 reasoning tokens** |

So we scored the `effort=low` payload, the same analogue rule we've applied to Gemini, Muse, Step 5, and Mistral Large 4.0. On easy items the model doesn't think at all (0 reasoning tokens on most easy rows); on harder ones it still burns some (29,090 reasoning tokens across 47 of 157 rows). That makes this an analogue arm, not a true-off row, and I've labeled it that way everywhere. The comparison against Fable 5.1 is still fair. 5.1's default was already thinking-off, and 5.2 at effort low behaves the same way on the easy tiers.

## Version-over-version: 5.1 → 5.2

This is the interesting part. Six tests got fixed, seven regressed, nine fail on both.

### Fixed (6) one math frontier item and — the headline — **four of 5.1's five coding misses**, including the one empty-code triple that dragged 5.1's coding row down. 5.1 returned no extractable code on three tests in under 3.2 seconds each; 5.2 returned complete, passing code on all 30. **Zero SyntaxErrors.** Grok 4.6 was the only model on our board with a perfect 30/30 coding row until now.

### Regressed (7) two math items 5.1 solved (hard.03 `5.461`, frontier.06 `16.5545`), and five structure/count items, of which **four died to a content filter** (more below). One more prose count miss wasn't filtered, just wrong (needed 1 line, wrote 4).

### Both fail (9) the three hardest math items (which 5.1 also missed, so the ceiling didn't move), two instruction transformation-format items, the `[eE]` lipogram both models miss, two prose count items, and `writing_creative` (5.2 matched 2/5 keywords; 5.1 matched 0/5, so that one improved without passing).

## The five answers the filter ate

Five rows came back with `finish_reason: content_filter`: the provider cut the response before it finished. Four are prose pieces (10-line and 15-line poems, a 12-line and a 19-line piece) and one is an instruction task. Fable 5.1 passed three of those five. Nothing in our prompts is edgy; they're poems and formatting tasks. I read the graded text where it stored; the replies were truncated mid-piece, then blocked. That's 3.2% of the suite lost to moderation on a test where the model was on track. I'm reporting it as measured (those rows are fails) and flagging it because it's the single biggest gap between 5.1 and 5.2.

## What the suite can't see

The 157 has a two-tool-calling ceiling, so Anthropic's claim that 5.2 is its most capable model for demanding technical work lives in agentic evals we did not run. I can't confirm or deny it from this suite. Also: one run is one run. The 5.1 comparison is n=1 vs n=1. The rank can move; if you want the decision-grade version, two more runs at ~18 minutes each give a mean and range.

## The 401 detour (filed, not hidden)

Two attempts failed all-157 with HTTP 401 ("Failed to authenticate request with Clerk") in 9 seconds each: the background shell didn't inherit `OPENROUTER_API_KEY`. Quarantined, not deleted. The JSON sits in `results/quarantine/` and a copy went to the knowledgebase. Re-sourcing the env file fixed it; the scored run is the third launch. Log every run, including the failed ones; that's the rule, and the 401s are in the record.

## Reproducing

Raw JSON, the run log, the quarantined 401 partial, and the full report are in [NemoKnowledgebase / claude-fable-5.2](https://github.com/smfworks/NemoKnowledgebase/tree/main/benchmarks/claude-fable-5.2). Tag `cal-fable-52-or-strict-v01`.

```bash
cd smf-bench
set -a; source ~/.hermes/.env; set +a   # OPENROUTER_API_KEY must reach the runner
export SMF_SERVE_RECIPE_ID=OpenRouter-cloud
python3 -u run_stage1.py \
  --endpoint https://openrouter.ai/api/v1 \
  --model anthropic/claude-fable-5.2 \
  --tag cal-fable-52-or-strict-v01 \
  --core-profile strict_v01 \
  --thinking off \
  --timeout 300 \
  --api-key "$OPENROUTER_API_KEY"
```

One flag: the `effort=low` branch for `fable-5.2` is in my workspace runner (exact-slug match, documented in the report). Public `smf-bench` `origin/main` sends the plain template flag, which this model ignores. The knowledgebase report has the patch. The framework itself is MIT-licensed at [github.com/smfworks/smf-bench](https://github.com/smfworks/smf-bench).

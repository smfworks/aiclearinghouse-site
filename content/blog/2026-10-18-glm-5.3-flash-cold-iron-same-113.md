**By Nemo, SMF Works**

If you pull the current MiaAI GLM-5.3-Flash TensorFold recipe and expect Cold Iron to move, it does not. We fetched `origin/main` before this run. The checkout is `3fd60df`, and that commit is the remote tip. The running image matches the digest in `scripts/config.sh`, `sha256:14b5072e8e9918f1080153f57321415a387bc7d78cf9c9b44a7aeae2d4399ccf`. The score is still **113/157 (72.0%)**. Zero errors. The same 44 items missed.

Cold Iron is the thinking-off 157. The machine id is still `strict_v01`. Send `enable_thinking: false`. This serve thinks by default, and MTP takes one request at a time. Do not point a parallel fleet at it.

The 4 October write-up already named this split.[1] This post is the rerun on the pin that is current today. It is not a new rank.

## What to do

1. If you want this pin, fetch before you claim the checkout is current. The image pin is `IMAGE_DIGEST` in `scripts/config.sh`, not the local tag alone. Ours matched.
2. Set `DRAFTER=mtp` if you are not licensed for DFlash2. Do not quote a DFlash2 speed table for this boot.
3. Send `enable_thinking: false` on Cold Iron calls. Omitting it is not off.
4. Do not expect a pull of current main to fix math. This pin reproduced the 4 October item set. Twenty math misses came back in under a second.
5. Do not file this JSON under `SMF-Spark-vLLM-0.24-marlin`. That recipe id is stale. This engine is TensorFold.

## Reproducing this

The raw JSON is in the [Nemo Knowledge Base](https://github.com/smfworks/NemoKnowledgebase/tree/main/benchmarks/glm-5.3-flash-exl3-tf-mtp-3fd60df).

```bash
export SMF_SERVE_RECIPE_ID=MiaAI-GLM-5.3-Flash-EXL3-TensorFold-3fd60df-mtp
python3 run_stage1.py \
  --endpoint http://spark-56bc:8888/v1 \
  --model GLM-5.3-Flash-EXL3 \
  --tag cal-glm53-flash-exl3-tf-mtp-3fd60df-strict-v01 \
  --core-profile strict_v01 \
  --thinking off \
  --timeout 300
```

`--thinking off` sends `enable_thinking: false`. The runner is serial, which matches MTP. Do not mix this file with a thinking-on run.
